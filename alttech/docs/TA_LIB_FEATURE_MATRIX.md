# TA-Lib feature vector

The `talib-core` feature set contains 995 ordered output columns generated by
the pinned TA-Lib 0.7.1 implementation. Functions with period and moving
average parameters are evaluated over the configured period ladder and moving
average types. The exact output names and positions are registered in the
feature-set schema.

## Warm-up and validity

The incremental feature engine retains a rolling window of 2048 bars. It marks
a vector `VALID` after the minimum bar count is reached and at least 60% of its
features have valid values. Individual outputs have independent validity bits;
`VALID` does not mean every column has converged.

Long-lookback outputs may remain invalid after the vector becomes `VALID`. The
period-200 T3 family is among the slowest groups. Consumers must use the
validity bitmap for each requested feature rather than infer availability from
the vector status or substitute the stored numeric placeholder for an invalid
value.

Accumulating outputs (`AD`, `ADOSC`, `OBV`) become valid only when the rolling
window is full, so their values use a consistent history span. A discontinuity
in source candles resets warm-up; values are not accumulated across a data gap.

## Consumers

Downstream modules use named projections for regime and reference-venue
analytics. AltML consumes the registered primary-venue feature vector. The
feature-set version and member order are stored with the vector so consumers
can interpret historical rows against the schema that produced them.

Inspect the registered catalog with:

```sql
SELECT position, output_name
FROM alttech.feature_set_members m
JOIN alttech.feature_set_versions v ON v.id = m.feature_set_version_id
WHERE v.name = 'talib-core'
ORDER BY position;
```
